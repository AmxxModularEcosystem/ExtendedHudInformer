# Extended HUD Informer

Плагин для AMX Mod X, выводящий игрокам **HUD-информеры** — персистентные `hud`-сообщения (не `dhud`), которые постоянно висят на экране и обновляются с заданной частотой.

Текст информера, частота обновления, цвет и расположение полностью настраиваются в JSON-конфиге. В тексте поддерживаются **плейсхолдеры** из `ParamsController` — как глобальные (`{map}`, `{time}`, `{players-count}` и т.д.), так и игровые (`{p:name}`, `{p:health}`, `{p:frags}` и др.).

Плагин использует встроенные плейсхолдеры `ParamsController@1.5.0` и полностью пригоден для использования на реальных серверах.

## Возможности

- Несколько информеров в одном конфиге (объект или массив объектов на файл, несколько файлов, вложенные папки).
- Настройка текста (с плейсхолдерами), цвета, позиции (X/Y), частоты обновления, времени удержания/появления/исчезания и HUD-канала.
- Встроенные плейсхолдеры ParamsController: глобальные (`{map}`, `{time}`, `{uptime}`, `{nextmap}`, `{players-count}`…) и игровые «колбечные» (`{p:health}`, `{p:armor}`, `{p:frags}`, `{p:ping}`, `{p:connect-time}`…) — всегда актуальны в момент обновления HUD.
- Скомпилированные шаблоны (`PCPH_CompileTemplate`) — текст разбирается один раз, обновление HUD максимально дёшево.
- Публичный API для других плагинов: поиск, включение/выключение, принудительный показ информера.

## Требования

- AMX Mod X **1.10.x**.
- [ParamsController](https://github.com/AmxxModularEcosystem/ParamsController) **1.5.0** или новее.
- Модули `cstrike` / `fun` не требуются — плагин игро-независимый.

## Установка

1. Соберите плагин (см. ниже) или возьмите готовый `.amxx` из релиза.
2. Скопируйте:
   - `ExtendedHudInformer.amxx` → `addons/amxmodx/plugins/`;
   - содержимое `configs/plugins/ExtendedHudInformer/` → `addons/amxmodx/configs/plugins/ExtendedHudInformer/`.
3. Добавьте в `addons/amxmodx/configs/plugins.ini`:
   ```
   params_controller.amxx
   extendedhudinformer.amxx
   ```
   `ParamsController` обязательно должен быть загружен (плагин использует его natives). Порядок не критичен, но оба должны быть в списке.
4. Перезапустите сервер или выполните `amxx reload extendedhudinformer.amxx`.

### Сборка

Проект собирается через [amxx-builder](https://github.com/AmxxModularEcosystem/amxx-builder):

```bat
amxb build
```

Манифест `amxbuild.yml` сам подтянет `ParamsController@1.5.0` как зависимость.

## Конфигурация

Конфиги лежат в папке `addons/amxmodx/configs/plugins/ExtendedHudInformer/`. Плагин рекурсивно обходит её и загружает все файлы с расширением `.json`. Файлы и папки, начинающиеся с `!` или `.`, пропускаются (например, `!disabled.json`).

Каждый файл может содержать **один объект информера** или **массив объектов**:

```json
[
    { ...информер 1... },
    { ...информер 2... }
]
```

### Поля информера

| Поле | Тип | Обязательно | По умолчанию | Описание |
|---|---|---|---|---|
| `Key` | строка | — | авто | Уникальный ключ информера (до 64 символов). Используется в API и логах. Если не задан (или пустой) — генерируется автоматически (`#auto:N`); это удобно, когда идентифицировать информер через API не нужно. Дубликаты явных ключей пропускаются с предупреждением. |
| `Text` | строка | ✅ | — | Текст информера с плейсхолдерами (до 512 символов). Многострочность — через `\n`. Компилируется в шаблон при загрузке. |
| `Color` | массив/объект/строка | — | `[200, 100, 0]` | Цвет текста. Форматы: `[R, G, B]`, `{"R":255,"G":255,"B":255}` (или `Red/Green/Blue`), `"255,255,255"`. |
| `X` | число | — | `-1.0` | Горизонтальная позиция в процентах экрана. `-1.0` — по центру, `0.0` — слева, `1.0` — справа. |
| `Y` | число | — | `0.35` | Вертикальная позиция в процентах экрана. `0.0` — сверху, `1.0` — снизу. |
| `UpdateTime` | число | — | `1.0` | Частота обновления, секунды. `<= 0` → `1.0`, меньше `0.1` → кламп до `0.1` (движок не поддерживает быстрее) с предупреждением в лог. |
| `HoldTime` | число | — | авто | Сколько секунд сообщение удерживается на экране. `0` (или не задано) → `UpdateTime + 0.5` (сообщение не мигает). |
| `FadeInTime` | число | — | `0.0` | Время плавного появления, секунды. |
| `FadeOutTime` | число | — | `0.0` | Время плавного исчезания, секунды. |
| `Channel` | целое | — | `-1` (авто) | HUD-канал. Допустимо `-1..4`. Для перманентных сообщений рекомендуется фиксированный канал `0-3` (см. «Советы»). |
| `Enabled` | bool | — | `true` | Включён ли информер. `false` — задача не запускается, информер можно включить через API. |

**Пример** (`ExampleInformers.json` уже включён в поставку):

```json
[
    {
        "Key": "welcome",
        "Text": "Welcome to {server-name}, {p:name}!\nMap: {map}\nPlayers: {players-count}/{max-players-count}\nTime: {time}",
        "Color": [0, 200, 100],
        "X": -1.0,
        "Y": 0.05,
        "UpdateTime": 1.0,
        "Channel": 1
    },
    {
        "Key": "player-stats",
        "Text": "Health: {p:health} | Armor: {p:armor}\nFrags: {p:frags} | Ping: {p:ping}\nConnected: {p:connect-time}",
        "Color": [255, 200, 0],
        "X": 0.02,
        "Y": 0.15,
        "UpdateTime": 0.5,
        "Channel": 2
    },
    {
        "Key": "server-info",
        "Text": "Server uptime: {uptime}\nNext map: {nextmap}",
        "Color": [200, 200, 200],
        "X": 0.02,
        "Y": 0.85,
        "UpdateTime": 5.0,
        "Channel": 3
    }
]
```

## Плейсхолдеры

Плейсхолдеры имеют вид `{key}` (глобальные) или `{prefix:key}` (групповые). Если плейсхолдер не зарегистрирован или группа неизвестна — он останется в тексте как есть.

Все плейсхолдеры предоставляются самим `ParamsController` — плагин своих не регистрирует. Полный актуальный список смотрите в репозитории `ParamsController`; ниже — наиболее полезные для информеров.

### Глобальные

| Плейсхолдер | Описание |
|---|---|
| `{map}`, `{real-map}` | Текущая карта |
| `{server-name}` | Название сервера |
| `{server-ip}` | IP сервера |
| `{date}` | Дата `ДД.ММ.ГГГГ` (обновляется раз в минуту) |
| `{time}` | Время `Ч:ММ:СС` (вычисляется при каждом обновлении) |
| `{datetime}` | Дата и время |
| `{players-count}` | Текущее количество игроков |
| `{max-players-count}` | Максимальное количество игроков |
| `{alive-count}` | Количество живых игроков |
| `{dead-count}` | Количество мёртвых игроков |
| `{bot-count}` | Количество ботов |
| `{human-count}` | Количество игроков-людей |
| `{uptime}` | Аптайм сервера: `Ч:ММ:СС` или `Nд Ч:ММ:СС` |
| `{gametime}` | Время текущей карты в том же формате |
| `{time-left}` | Время до конца карты |
| `{nextmap}` | Следующая карта (cvar `amx_nextmap`); `-`, если не задана |
| `{mod}` | Название мода |
| `{amx-version}` | Версия AMX Mod X |

### Игрока (группа `p`)

Групповые плейсхолдеры подставляются **для каждого игрока индивидуально** в момент обновления HUD:

| Плейсхолдер | Описание |
|---|---|
| `{p:name}` | Имя игрока |
| `{p:authid}` | AuthID игрока (например `STEAM_0:1:12345`) |
| `{p:ip}` | IP игрока |
| `{p:userid}` | UserID игрока |
| `{p:index}` | Индекс (id) игрока |
| `{p:health}` | Здоровье игрока (0 для мёртвых) |
| `{p:armor}` | Броня игрока |
| `{p:frags}` | Фраги игрока |
| `{p:deaths}` | Смерти игрока |
| `{p:ping}` | Пинг игрока |
| `{p:loss}` | Потери пакетов игрока |
| `{p:connect-time}` | Время игрока на сервере в формате `Ч:ММ:СС` |
| `{p:team}` | Номер команды игрока |
| `{p:team-name}` | Название команды игрока |
| `{p:alive}` | `1`, если игрок жив, иначе `0` |
| `{p:bot}` | `1`, если игрок — бот, иначе `0` |

### Механизм

Игровые плейсхолдеры (`health`/`frags`/`ping` и т.д.) — **реактивные**: `ParamsController` запрашивает значение у колбека при каждом форматировании, поэтому они всегда актуальны без дополнительных событий. Перед форматированием HUD плагин кладёт в стек группы `p` контекст текущего игрока (`PCPH_Group_PushIntContext`), а после — снимает его (`PCPH_Group_PopContext`). Для обновления HUD используется скомпилированный шаблон (`PCPH_CompileTemplate` + `PCPH_FormatTemplate`) — строка с плейсхолдерами разбирается один раз при загрузке конфига, дальнейшее обновление не выполняет сканирование строки.

## Советы

- **HUD-каналы.** Для постоянного сообщения задавайте фиксированный `Channel` (`0-3`). Если оставить `-1` (авто), несколько информеров могут «перебивать» друг друга, а при совпадении таймингов возможен фликер. Каждый информер должен использовать свой канал. Канал `4` используется игрой (радар/служебные сообщения) — лучше его избегать.
- **Многострочность.** Используйте `\n` в `Text`. Не забывайте, что JSON требует экранирования — `\n` в файле конфига так и пишется как `\n`.
- **Лимиты.** `Text` ограничен 512 символами (это ограничение типа `PH-Template`). Сегменты текста длиннее 512 символов обрезаются самим ParamsController.
- **`HoldTime`.** Если сообщение мигает — увеличьте `HoldTime` так, чтобы оно было больше `UpdateTime` (по умолчанию это делается автоматически).
- **Изменение конфига.** После правки JSON выполните `amxx reload extendedhudinformer.amxx` — конфиг перечитается, все шаблоны перекомпилируются.
- **Отключение информера без удаления.** Поставьте `"Enabled": false` или переименуйте файл в `!something.json`.

## API для разработчиков

Подключите `<ExtendedHudInformer>` в своём плагине. Перед использованием убедитесь, что библиотека загружена:

```pawn
if (!LibraryExists("ExtendedHudInformer", LibType_Library)) {
    // плагин ExtendedHudInformer не загружен
}
```

```pawn
native ExtendedHudInformer_Init();
// Принудительная инициализация (вызовется ParamsController_Init + загрузка конфигов).
// Идемпотентна.

native T_ExtendedHudInformer:ExtendedHudInformer_Find(const key[]);
// Поиск информера по Key. Invalid_ExtendedHudInformer (-1), если не найден.

native bool:ExtendedHudInformer_IsEnabled(const T_ExtendedHudInformer:informer);
// Включён ли информер (запущена ли его задача обновления).

native ExtendedHudInformer_SetEnabled(const T_ExtendedHudInformer:informer, const bool:enabled);
// Включить/выключить информер на лету.

native ExtendedHudInformer_Show(const T_ExtendedHudInformer:informer, const playerIndex = 0);
// Принудительно показать информер сейчас. playerIndex = 0 — всем игрокам.
```

Пример — выключить информер на время события:

```pawn
new T_ExtendedHudInformer:informer = ExtendedHudInformer_Find("player-stats");
if (informer != Invalid_ExtendedHudInformer) {
    ExtendedHudInformer_SetEnabled(informer, false);
}
```

## Отладка

- Все этапы инициализации и регистрации пишутся в лог сервера с префиксом `[INFO]`.
- Ошибки конфига (неверный тип поля, дубликат `Key`, пустой `Key` и т.п.) пишутся в лог с префиксом `[JSON][WARNING]` и указанием файла — проблемный информер пропускается, остальные продолжают работать.
- Если папка конфигов не найдена или JSON-файл не парсится — плагин аварийно завершает загрузку (как и другие плагины экосистемы) с явным сообщением в консоли.
- Список зарегистрированных типов параметров: `params_controller_types` (srvcmd).
- Типичная проблема: плагин не загружается с ошибкой «Native not found». Причина — `ParamsController` не загружен или загружен после `ExtendedHudInformer`. Проверьте `plugins.ini`.
